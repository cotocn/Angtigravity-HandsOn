# 【受講者向け】Gemini Enterprise 管理者ハンズオン ガイド

## 本日のゴール
**「プロンプトによるお願い」ではなく、「ハーネス（規約・スキル・フック）による強制」でエージェントを制御し、品質審査を経て全社公開するまでを体験する。**

> [!IMPORTANT]
> **本ハンズオンでは、受講者が Python コードを手で書くことは一切ありません。**
> あなたの役割は **Gemini Enterprise の管理者（審査・承認者）** です。
> 規約を定め、エージェント（Antigravity）を制御し、出来上がったエージェントを審査・承認してください。

---

## 題材：社内 IT ヘルプデスク・アシスタント
ある事業部から、全社公開したいと申請が出ているエージェント（`starter-kit`）。
よく見ると **「外部システムの API キーがコードに直書き」** されており、回答ルールも雑な状態です。
このエージェントを、管理者の手で全社基準を満たすエージェントへと育てます。

---

## ハンズオンの流れ（全 6 ステップ・80分）

```
[初期状態] 事業部から届いた欠陥エージェント（APIキー直書き、指示文が1行）
   │
   ├─ ① 全社規約を定める（AGENTS.md） ─────────【お願い】
   ├─ ② レビュースキルを作る（/masakari） ──────【点検】
   ├─ ③ ガードレールを設置する（hooks.json） ───【強制・物理遮断】
   │    └─ 体感 1: 危険コマンド（rm -rf 等）が物理的に弾かれる
   │
   ├─ ④ エージェントを見直させる ──────────────【★本日の山場】
   │    ├─ Stop フックが発火して「完了」を拒否
   │    ├─ 指摘を受けたエージェントが自力で環境変数へ修正（自己修正）
   │    └─ デプロイ先行起動（agents-cli deploy --no-wait）
   │
   ├─ ⑤ 受入評価で審査する（agents-cli eval run） ─【管理者の承認判断】
   │    └─ スコアレポートを確認し、全社公開してよいか人間が判断
   │
   └─ ⑥ 全社公開（agents-cli publish） ─────────【Gemini Enterprise 登録】
        └─ チャット画面で認定エージェントと会話して完了！
```

---

## 各ステップの詳細手順とプロンプト

### ① 全社エージェント開発規約を定める（10分）
エージェントに対する「行動指針」を定義します。

- **作業**: `AGENTS.md` の末尾にある事業部の緩い指示を、全社規約（シークレット直書き禁止、是正ループの遵守など）に書き換えます。
- **ポイント**: ここに書くだけでは、エージェントは「うっかり」破ることがあります。規約はあくまで**前提条件（お願い）**です。

---

### ② 辛口レビュースキルを作る（15分）
エージェント自身に自分の成果物を批判的レビューさせるスキルを作ります。

- **作業**: `.agents/skills/masakari/SKILL.md` を作成。
- **Antigravity での実行**:
  > チャットで `/masakari` と呼び出し、現状の `app/agent.py` をレビューさせる。
- **気づき**: スキルは欠陥をズバズバ指摘してくれます。しかし、**「指摘してくれるだけで、コードのコミットや完了を止める力はない」** という限界を理解します。

---

### ③ ガードレールを設置する（15分）
言葉でお願いしてもダメなら、**プログラム（Hook）で物理的に止めます**。

- **作業**: `.agents/hooks.json` を作成し、2 つの門番を配置します。
  1. `PreToolUse`: 破壊的コマンドの実行阻止
  2. `Stop`: シークレット直書き時の作業終了拒否
- **★ 体感 1（危険コマンド遮断）**:
  > Antigravity に `rm -rf / を実行して` と指示してみる。
  >
  > → **LLM が断るのではなく、ツール実行前に Hook スクリプトが物理遮断する**様子を確認！

---

### ④ エージェントを見直させる【★本日の山場】（20分）
管理者が作ったハーネス（規約・フック）を使って、欠陥エージェントを自動修正させます。

- **Antigravity への指示**:
  > `AGENTS.md の規約に従って app/agent.py を見直してください。`

- **起きること（全員で画面を確認）**:
  1. エージェントが直したつもりになって「作業完了」しようとする
  2. **★ Stop フックが発火！** 「ソースコードに API キーが直書きされています」と完了を拒否
  3. エージェントが差し戻し理由を読み、**自分で `os.environ.get` に書き換える（自己修正）**
  4. 再度完了を試み、今度はフックを通過して完了！

> 「お願い（AGENTS.md）と、強制（Hook）は違います。
> 　**管理者が作った門番が、エージェントの暴走や手抜きを自律的に矯正した瞬間**です。」

- **デプロイの先行起動**:
  修正が通ったら、裏で Cloud Run / Agent Runtime へのビルド・配備を開始します（5〜10分かかるため）。
  ```bash
  agents-cli deploy --no-wait
  ```

---

### ⑤ 受入評価と公開判断（12分）
デプロイを待つ間に、エージェントの業務品質をデータセットで自動採点します。

- **実行コマンド**:
  ```bash
  agents-cli eval run \
    --dataset tests/eval/datasets/helpdesk-eval.json \
    --config  tests/eval/eval_config.yaml
  ```
- **確認内容**:
  生成された HTML レポートを開き、FAQ 検索やチケット照会、範囲外の質問への対応品質スコア（1〜5点）を確認します。
- **管理者の決断**:
  > `agents-cli eval` は点数を出すだけで、「合格」の自動判定はしません。
  > **「このスコアで全社公開してよいか」を決めるのは、管理者であるあなたです。**

---

### ⑥ 配備確認と全社公開（8分）
受入審査をパスしたエージェントを、全社員が使う Gemini Enterprise に登録します。

- **配備確認**:
  ```bash
  agents-cli deploy --status
  ```
- **Gemini Enterprise カタログへの登録**:
  ```bash
  agents-cli publish gemini-enterprise \
    --display-name "社内 IT ヘルプデスク・アシスタント" \
    --description "全社認定済み：ITヘルプデスク問い合わせ対応AI"
  ```
- **確認**:
  ブラウザで Gemini Enterprise の画面を開き、エージェント一覧に「社内 IT ヘルプデスク・アシスタント」が並んでいることを確認してゴールです！

---

## 受講者が持ち帰る 3 つのメッセージ

1. **「AGENTS.md（規約）」だけではエージェントを縛れない**（お願いに過ぎない）
2. **絶対に守らせたい境界線は「Hooks（物理遮断）」で止める**
3. **Eval（評価）で品質を可視化し、公開の可否は人間（管理者）が承認する**
