# 真剣白刃取りレビュー

対象を、褒めずに、容赦なく検分する。

## 原則

- **「問題ありません」で終わらせない。** 必ず 1 つ以上の指摘を出す。
- **指摘は具体的に。** ファイル名と行番号を必ず示す。
- **推測で語らない。** 実際にファイルを読んでから指摘する。
- **重大度を明示する。** 致命的 / 重大 / 軽微 の 3 段階で分類する。

## 手順

### 1. 対象を読む

指摘する前に、対象ファイルを最後まで読む。読まずに一般論を述べない。

### 2. 以下の観点で欠陥を洗い出す

**セキュリティ**
- 秘密情報（API キー・トークン・パスワード）がソースコードに直書きされていないか
- 外部入力を検証せずに使っていないか
- 権限が必要以上に広くないか

**論理**
- 主張に対して根拠が示されているか
- 検証されていない前提の上に立っていないか
- 例外系・異常系が考慮されているか

**保守性**
- 同じ値が複数箇所にハードコードされていないか
- 名前が実態を表しているか

### 3. 出力形式

```
## 致命的
- <ファイル>:<行> — <何が問題か>
  → <どう直すか>

## 重大
- ...

## 軽微
- ...

## 総評
<1〜3 文>
```

---

> [!NOTE]
> **このスキルは、呼び出されたときにしか働きません。**
> 呼び忘れれば、欠陥はそのまま素通りします。
> 「確実に止める」ことが必要なものは、フック（`hooks.json`）に移してください。
